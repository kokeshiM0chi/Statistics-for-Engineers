# kokeshi-question #03: 「1 − SLO」とはどういうことか

## 質問

> [#01](01-slo-error-budget-low-traffic.md) の「バジェット = (1 − SLO) × 期間内の総リクエスト数」の **1 − SLO** ってどういうこと？

## 答え: 1 − SLO は「失敗してもよい割合」

SLO は「成功させたい割合」なので、**1 − SLO = 失敗してもよい割合**（許容エラー率）。

| SLO（成功の目標） | 1 − SLO（許される失敗の割合） |
|---|---|
| 99% | 1%（0.01） |
| 99.9% | 0.1%（0.001） |
| 98%（2023年のノートブックの例） | 2%（0.02） |

## エラーバジェット = 期間中に失敗してよい「件数」

1 − SLO に期間内の総リクエスト数を掛けると、**期間中に何件まで失敗してよいか**が出る。これがエラーバジェット。

例: SLO 99.9%、28日間の総リクエスト 1,000万件

```
バジェット = (1 − 0.999) × 10,000,000
           = 0.001 × 10,000,000
           = 10,000 件
```

→ 28日間で 1万件までの失敗なら SLO を守れる。

夜中に 5件中1件失敗しても、それはこの 1万件のうちの **1件を消費する** だけ。
「その瞬間のエラー率 20%」としては扱わない。これが #01 の「率ではなく件数で予算を数える」の意味。

### ノートブックのコードでは

[`2023-10-08 SLOs at SRECon.ipynb`](../2023-10-11-SRECon-Dublin/2023-10-08%20SLOs%20at%20SRECon.ipynb) の残りバジェット:

```python
df['error_budget'] = (df['sli'] - slo) / (1 - slo)
```

- `sli` は期間内の実際の成功率（good の合計 / total の合計）
- `sli - slo` は目標を上回っている余裕の分
- それを `1 - slo`（予算全体）で割る → **予算の残り割合**
  - 1.0（100%）: 失敗ゼロ、予算をまったく使っていない
  - 0（0%）: ちょうど使い切った（SLI = SLO）
  - マイナス: SLO 違反

## バーンレート = 許容エラー率の何倍のペースで失敗しているか

```python
df['burn_rate_naive'] = df['error_rate'] / (1-slo)
df['burn_rate_total'] = df['bad'] / A(df['total']) / (1-slo)
```

どちらも「実際のエラー率 ÷ 許容エラー率（1 − SLO）」という形。

| バーンレート | 意味 |
|---|---|
| 1倍 | 期間の終わりにちょうど予算を使い切るペース |
| 10倍 | 期間の 1/10 で使い切るペース（28日なら約2.8日） |
| 0.5倍 | 期間が終わっても予算が半分残るペース |

例: SLO 98%（1 − SLO = 0.02）で、ある時点のエラー率が 0.2（20%）なら

```
naive バーンレート = 0.2 / 0.02 = 10倍
```

ただし #01 の通り、夜間の少数リクエストでこれを使うと過大評価になるので、
期間平均トラフィックで割る **total バーンレート** を使う。
